Currently developing

Django at work is all synchronous, so I've been learning FastAPI on the side to get comfortable with asynchronous programming — async request handling, dependency injection, and non-blocking I/O, the parts that don't really come up in a typical Django project.

I'm pairing that with SQLAlchemy and PostgreSQL, building small services from scratch so I'm designing the schema, writing the queries, and managing the database connection myself instead of relying on Django's ORM to handle it.

The point is being able to pick the right tool for the job — knowing when a synchronous framework is the simpler choice and when async actually earns its complexity.
